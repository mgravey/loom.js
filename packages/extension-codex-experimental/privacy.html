Loom.js Companion privacy disclosure

This bundled disclosure summarizes the extension build. The linked public policy contains the complete publisher, retention, rights, and contact information.

Single purpose

Authenticate a user-initiated Loom session and provide its authorized workbench with the short-lived credentials required for a direct model request and relay that request only when direct browser access fails before an HTTP response. For custom Responses servers, route the authorized website’s model requests through a user-configured extension connection.

Information handled

  • A refresh credential and account-routing ID stored in trusted extension session storage by default. If you explicitly select “Remember sign-in on this Chrome profile,” that pair remains in local extension storage after Chrome exits.
  • Short-lived credentials returned to the authorized workbench and not persisted by Loom.
  • Model prompts, selected project context, tool traffic, and response streams only during a fallback relay after the direct browser request fails before an HTTP response.
  • Authentication status, logout acknowledgement, access token, and account-routing ID returned to the authorized Loom origin.
  • Exact website origins approved by the user in trusted extension UI. Approved origins remain in local extension storage until revoked; pending first-contact requests remain session-only.

Persistent local extension storage is not an encrypted credential vault. Use the remember option only on a private computer; someone able to use the same unlocked Chrome profile may be able to use the connected account. Logout and disabling the experiment remove session and persistent authorization copies.

Model server connections

Responses-compatible, Anthropic and Gemini HTTP(S) server endpoints and optional API keys are stored in trusted local extension storage until edited, removed, extension data is cleared, or the extension is uninstalled. Keys are not returned to websites. Chrome host access is requested when you save a connection. Model discovery reads the saved servers’ provider-specific model catalogues using their individual keys. Only approved servers’ model IDs and labels are returned to the website. Website approval applies to every configured server and remains independent of ChatGPT sign-in or disabling its experiment. Custom model requests and responses pass transiently through the extension to that saved server; no ChatGPT credentials are attached. HTTP endpoints do not encrypt traffic. Local storage is not an encrypted credential vault.

Use Remove beside a custom connection to delete its profile and key. ChatGPT logout and disabling the Codex experiment do not delete independent custom connections. Remove prevents new requests; running requests may finish. Revoke host permissions separately in Chrome.

Optional Google account experiment

Developer builds configured with a Google OAuth client can request Google Cloud access through Chrome Identity. Tokens remain in Chrome's OAuth cache and are used only for fixed Code Assist account checks and generation. Companion stores a revocable session marker, optional project ID and manually configured model IDs. Sign out clears local authorization and the extension's Chrome token cache. Running requests may finish. The standard build does not enable this OAuth experiment.

Not collected

The extension does not request or inspect browsing history, unrelated page content, cookies, geolocation, advertising identifiers, or analytics telemetry.

Retention and deletion

Use Remove stored authorization, disable the bridge, clear extension data, or uninstall to remove extension-owned authentication state. This removes local state; it does not itself revoke a grant held by the provider.
